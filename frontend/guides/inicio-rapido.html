Inicio rápido

Secuencia mínima para dejar operativo un tenant nuevo y abrir su primera consola. Los ejemplos usan marcadores: reemplazalos por valores de tu entorno y nunca pegues credenciales en tickets ni documentos.

Antes de empezar confirmá que el despliegue de infra terminó, que los grupos del inventario tienen hosts y que el gateway HTTPS responde. La topología se toma del inventario, no de suposiciones.

Secuencia operativa

1
Identificarte. Abrí la UI con tu usuario. Si el modo es hybrid podés usar login local u OIDC; el gateway emite un JWT con sub, role y roles[].
2
Verificar tus capacidades. Revisá que tu rol tenga los perfiles necesarios: tenants_manager para dar de alta, access_metrics para abrir métricas, etc. (IAM y ABM).
3
Crear el tenant. POST /api/v1/admin/tenants devuelve 202 con id y job_id. No esperes infra en la respuesta: el alta es background.
4
Seguir el job. Sondeá GET /api/v1/admin/jobs/{job_id} hasta succeeded. Las fases son assigning_ids → seeding_datasources → auto_placement → activating → deploying_vmalert → regenerating_scrapes → provisioning_parses → done.
5
Comprobar acceso. La concesión automática se hizo solo en role_tenants para admin y tenant_manager. Si otro usuario debe verlo, asignalo desde el ABM o por una solicitud aprobada.
6
Abrir una consola. Desde la tarjeta correspondiente se pide un ticket con el scope; el navegador navega a /ui/redeem/<ticket> y queda una cookie de sesión.
7
Verificar alertas. Si el tenant tiene has_alerts, debe existir la unit anomalia-vmalert-<slug>.service en el puerto 8880 + tenant_id.

Comandos de referencia

curl -X POST <gateway>/api/v1/admin/tenants \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{"name":"tenant-ejemplo","type":"metrics","has_alerts":true,"placement_mode":"auto"}'

curl <gateway>/api/v1/admin/jobs/<job_id> \
  -H "Authorization: Bearer <access_token>"

curl -X POST <gateway>/api/v1/ui/ticket \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{"tenant_id":42,"scope":"metrics"}'

El gateway es el único punto de entrada. Los puertos de lectura de Victoria están aislados por firewall y no deben exponerse al navegador.

Lo que NO hacer

No ejecutar deploy/destroy desde esta guía. No pegar tokens ni contraseñas en carpetas compartidas. No insertar user_tenants durante el alta de un tenant. No editar reglas de tenants internos: están protegidas con 409.
